# Социальное такси

Система для службы социального такси: сайт диспетчерской и Android-приложение водителя.

| Часть | Где | Технологии |
|---|---|---|
| Сайт диспетчерской | `web/` | React + Vite + TypeScript + Tailwind |
| Приложение водителя | `driver_app/` | Flutter (Android) |
| База, вход, realtime | `supabase/` | Supabase (Postgres, Auth, Realtime, Edge Functions) |
| Выкладка на сервер | `deploy/` | Docker Compose за Traefik |

Боевой адрес: **https://staxi.apsoftgroup.ru**. Логин и пароль администратора лежат на сервере
в файле `.credentials` в папке стека.

## Как это работает

**Поездка** — это дорога в одну сторону: забрать клиента в указанное время и отвезти по адресу.
Заказ «туда и обратно» создаёт две связанные поездки. Машина может везти несколько клиентов
одновременно (попутно) — система ничего не запрещает, только подсказывает, кто ещё едет в это время.

**Статусы поездки** (меняет водитель в приложении, диспетчер может поправить вручную):

`Запланирована` → `Едет к клиенту` → `На месте, ждёт` → `Везёт клиента` → `Выполнена`, и отдельно `Отменена` (с причиной).

**Подтверждение изменений.** Любой новый или изменённый диспетчером заказ водитель должен
«принять» в приложении. На доске у заказа видно «принял» или «не видел» — если водитель долго
не видит изменение, диспетчер звонит ему.

**Отказы.** Если клиента взять не получилось, диспетчер фиксирует отказ (прямо из формы заказа
или кнопкой «Отказ»). В «Статистике» спрос = принятые поездки + отказы, отсюда считается,
сколько машин нужно на самом деле.

**Карта.** Пока водитель «на линии», приложение передаёт положение машины; диспетчер видит
машины на карте и то, кого они сейчас везут.

**Роли:** администратор (всё + сотрудники и пароли), диспетчер (сайт), водитель (только
приложение, видит заказы своей машины и клиентов из этих заказов).

## Первые шаги на боевом сайте

1. Войти администратором (данные в `.credentials` на сервере).
2. «Настройки → Сотрудники»: завести диспетчеров и водителей (логин + пароль).
3. «Настройки → Машины»: добавить машины, закрепить водителей.
4. «Настройки → Места»: частые адреса (поликлиники, реабилитационные центры).
5. «Настройки → Общее»: телефон диспетчерской (кнопка звонка в приложении водителя).

## Демо-режим

Для показа системы есть отдельная демо-база с вымышленными клиентами (стек `staxi-demo` на том
же сервере, API по адресу `https://staxi.apsoftgroup.ru/demo/...`). Боевая база с ней никак не
связана.

- **Сайт:** на странице входа кнопка «Демо-режим» — вход без пароля. Сверху жёлтая полоса с
  кнопками «Начать демо заново» (пересоздаёт данные, расписание строится вокруг текущего
  времени) и «Выйти из демо».
- **Приложение водителя:** кнопка «Демо-режим» на экране входа — вход демо-водителем «Машины 1».
- **Оживление:** «Машина 2» сама ездит по карте, принимает заказы и проходит статусы;
  «Машину 1» ведёт человек с телефона (пока телефон не передаёт координаты, по карте ездит и она).
- Каждую ночь (04:10) демо-база сбрасывается сама. Логика — в `supabase/demo/demo.sql`,
  этот файл применяется только к демо-базе.

## Локальный запуск (для разработки)

Нужны Docker, Supabase CLI, Node + pnpm, Flutter.

```bash
supabase start                      # локальная база на портах 5642x
cd web && pnpm install
docker exec -i supabase_db_soctaxi psql -U postgres -d postgres < ../supabase/demo/demo.sql
node scripts/seed.mjs --demo        # демо-пользователи и данные; логины и пароль — в начале scripts/seed.mjs
pnpm dev                            # http://localhost:5376
```

`web/.env.local` должен содержать `VITE_SUPABASE_URL=http://127.0.0.1:56421` и
`VITE_SUPABASE_ANON_KEY` (значение `ANON_KEY` из `supabase status -o env`).

Приложение водителя — см. `driver_app/README.md`.

## Приложение водителя

Установочный файл: **https://staxi.apsoftgroup.ru/app/soctaxi-driver.apk** (ссылка есть и на сайте:
«Настройки → Сотрудники»). На телефоне нужно разрешить установку из браузера, затем при первом
запуске — уведомления и доступ к местоположению.

Ключ подписи приложения (`driver_app/android/app/soctaxi-release.jks` и
`driver_app/android/key.properties`) в git не хранится — **сделайте его копию**: без него
обновление нельзя будет поставить поверх уже установленного приложения.

## Выкладка на сервер

```bash
cp deploy/deploy.local.example deploy/deploy.local   # один раз: адрес сервера, папка, домен
./deploy/deploy.sh
```

`deploy/deploy.local` в git не хранится. На сервере нужны Docker и Traefik с внешней сетью `web`
и резолвером сертификатов `letsencrypt`.

Скрипт копирует конфигурацию боевого и демо-стека, применяет новые миграции из
`supabase/migrations`, обновляет серверную функцию, собирает сайт и выкладывает APK. Секреты (`.env`) создаются на сервере один раз и больше не
трогаются. Повторный запуск безопасен.

Резервная копия базы: на сервере в папке стека `./backup.sh` (в файле есть строка для cron).

## Структура базы

Миграции: `supabase/migrations/`. Главное:

- `profiles` — сотрудники и роли; `vehicles` — машины (водитель, число мест, ориентир нагрузки);
- `clients` — клиенты (контакты, адрес, диагноз, передвижение, сопровождающий);
- `trips` — поездки; `trip_events` — журнал изменений каждой поездки;
- `refusals` — отказы; `places` — частые адреса;
- `vehicle_locations` — последнее положение машин; `vehicle_feed` — сигнал приложению водителя.

Доступ ограничен на уровне базы (RLS): без входа не видно ничего; водитель читает только своё и
меняет статусы только через функции `driver_set_status` / `driver_ack` / `driver_report_location`.
